# Создание резюме Go-разработчика

## 1. Поиск вакансий на HeadHunter

### Поисковый запрос

Для поиска подходящих позиций рекомендуется использовать следующий булевый запрос:
```
Golang developer OR Go разработчик OR Golang-разработчик
```
**Целевые параметры:** локация (например, Москва), опыт работы 3–6 лет.

### Фильтрация по отраслям

Целесообразно фильтровать вакансии по основным для Go-разработки отраслям:
- Информационные технологии, системная интеграция, интернет (Интернет-компании, Разработка ПО)
- Розничная торговля (E-commerce)
- Телекоммуникации, связь
- Услуги для бизнеса (B2B)
- Финансовый сектор (Финтех)

## 2. Анализ вакансий

Отобранные вакансии следует сгруппировать по отраслям и проанализировать (рекомендуется использовать LLM, см. [[Obsidian Sync/30 Interests 1/31 Programming/Go/База для собесов/Все про резюме/Промпты LLM для вакансий]]).

### Специфика требований по отраслям

**Ритейл / E-commerce**
- **Задачи:** разработка микросервисной платформы, управление товарами, интеграция с логистическими и складскими системами.
- **Ожидаемый стек (плюс):** Python, Java, Highload опыт, ClickHouse.

**Логистика / Телеком / Доставки**
- **Задачи:** разработка внутреннего инструментария (CLI), взаимодействие с Kubernetes, развитие PaaS, поддержка высоконагруженных систем.
- **Ожидаемый стек (плюс):** 5G, IoT, AWS/GCP, TCP/IP, RabbitMQ, Kafka, Kubernetes, NoSQL.

**Финтех / Банкинг**
- **Задачи:** архитектура банковских сервисов, интеграция в банковские платформы, кредитные конвейеры, мониторинг и анализ инцидентов.
- **Ожидаемый стек (плюс):** SSL, PCI DSS, ETL, gRPC, C/C++, PSD2.

**Отраслевая фокусировка**
Резюме должно отражать фокус на конкретном направлении. Должность в резюме должна совпадать с желаемой (например, "Golang-разработчик"). Смешение должностей (Java developer, Fullstack, DevOps) в желаемой позиции снижает конверсию.

## 3. Оформление опыта работы

Оптимальная продолжительность работы на одном месте составляет от 1 до 3 лет.

### Выбор компаний

Рекомендуется указывать названия реальных продуктов или крупных компаний. При работе в аутсорсинге или аутстаффинге следует упоминать конечного заказчика (например, «Аутсорс-компания, проект для Альфа-банка»). Следует избегать абстрактных названий («Стартап», «ИП», аббревиатур вроде «ООО "Ромашка"»).

### Структура описания опыта

Для каждого места работы (особенно последнего) описание должно включать:
1. Наименование компании и ссылку.
2. Отрасли компании.
3. Должность (Golang-разработчик).
4. **Контекст проекта:** над чем велась работа, масштаб и бизнес-домен, размер команды, зона ответственность.
5. **Стек:** 10-15 релевантных технологий.
6. **Достижения:** 6-8 конкретных измеримых результатов.

#### Форматирование достижений (XYZ)

Достижения формулируются по принципу: **результат** (что сделано) + **метод** (как сделано) + **бизнес-ценность** (зачем).

> [!example] Примеры достижений
> - Настроил систему мониторинга на базе Prometheus и Grafana, что позволило выявлять деградацию API в режиме реального времени.
> - Внедрил слой кэширования на базе Redis, снизив среднее время ответа API и уменьшив нагрузку на реляционную БД в часы пик.
> - Спроектировал асинхронную обработку заказов с использованием Kafka и gRPC, обеспечив масштабируемость системы до 50 000 RPS.
> - Провел миграцию логистических данных из PostgreSQL в Cassandra для обеспечения горизонтального масштабирования проекта.

**Важно:** следует избегать использования необоснованных процентов (например, "ускорил на 30%"), если их нельзя аргументировать конкретными профилировками или метриками. Вся информация читается по F-паттерну: самое важное для скрининга должно находиться в начале описания.
